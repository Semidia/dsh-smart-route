# dsh-smart-route 外部通道接入设计（C 档实施蓝图）

> 状态：设计已定稿，待实施（用户确认后按 C 档执行）。
> 实施计划见：`../PLAN.md`（含已确认决策点、质疑回应、验收标准、回退方案）。
> 目标：让用户只需在 Harness **之外**的某个目录（如 opencode 文件夹）放一个「本地 url + key」通道文件，智能路由插件自动扫描、纳管、转发，全程不改 `settings.yaml`、`cordis.patch.yml`、`llm-pi-ai`。

---

## 1. 背景与目标

### 1.1 需求原文

> 有没有办法让我的智能路由插件实现这个功能——我只需要在本机 harness 以外的一个地方（比如 opencode 的文件夹），打造一套本地 url+key 的结构，就行了。

### 1.2 目标

1. **通道配置与 Harness 解耦**：通道定义（baseUrl、key、models）存放在 Harness 之外的目录，smart-route 自动发现。
2. **零 Harness 配置改动**：不写 `settings.yaml`、不注册 llm-pi-ai provider、不改组合。
3. **即插即用**：放文件即生效；改文件热更新；删文件即下线。
4. **保持模型列表干净**：模型选择器仍只显示链名（smart-route 虚拟 provider 设计不变）。

### 1.3 非目标（本期不做）

- 不做「从 opencode.jsonc / auth.json 直接解析」（格式耦合，已确认不做增量导出脚本）。
- **不自动生成「外部链」**：外部通道不自动进入任何链；用户按需在设置卡**手动新建链 / 填写渠道**，url + key 由插件从外部文件自动补全（用户只需填通道 id 与模型 id）。
- 不做鉴权/多用户（绑定 127.0.0.1 的本地信任模型）。

## 3. 总体设计

```
用户放文件                       smart-route (Host)
┌────────────────────┐  扫描   ┌─────────────────────────────────────┐
│ 通道目录/            │ ─────▶ │ apply(): scan + fs.watch/轮询         │
│   opencode-free.jsonc│         │   │                                │
│   myapi.json        │         │   ▼                                │
└────────────────────┘         │ 外部通道集合 externalChannels        │
                               │   │ 建链引用(provider=通道id)          │
                               │   ▼                                │
                               │ chains[] ──entry──▶ 渠道池补全url/key  │
                               │   │                                │
                               │ SmartRouteAdapter.stream()          │
                               │   └─ openAiCompatStream(baseUrl)    │
                               └─────────────────────────────────────┘
```

- 新增 Config 字段 `channelDir`（空 = 不启用外部通道）。
- `apply()` 启动时全量扫描一次；`fs.watch` 监听目录变更（自动主机制，秒级）；另注册本地 HTTP 路由 `POST /api/dsh-smart-route/refresh` 提供**手动刷新**（脚本/cmd 一键触发）。**不引入常驻轮询**——通道文件变更本就是低频人工编辑，轮询是空转。
- 外部通道作为**半注册渠道池**（`externalChannels: id -> {baseUrl, key, models}`），不自动进链；用户建链时写 `provider = 外部通道 id`（如 `opencode-free`），请求时插件从渠道池**自动补全 baseUrl / key / contextWindow**——复用现有 `chainEntries` / 冷却 / 降级管线，**零改动转发核心**。

## 4. 外部通道文件格式

一个文件 = 一个通道（一个 baseURL）。支持 `.jsonc`（带注释）与 `.json`。放在 `channelDir` **顶层**（不递归，保持简单）。

```jsonc
// opencode-free.jsonc —— 示例：OpenCode 桥接免费 DeepSeek
{
  // 必填：通道唯一 id（文件名可同名，冲突时后者覆盖并记日志）
  "id": "opencode-free",
  // 展示名，用于状态面板
  "displayName": "OpenCode 免费 DeepSeek",
  // 必填：OpenAI 兼容根 URL（不带 /chat/completions 后缀）
  "baseUrl": "http://127.0.0.1:4107/v1",
  // key 二选一：明文（仅限本地文件，勿提交 git）
  "apiKey": "",
  // key 二选一：环境变量名，优先级高于 apiKey（走 launchEnv，与现有 apiKeyEnv 一致）
  "apiKeyEnv": "OPENCODE_BRIDGE_API_KEY",
  // 必填：至少一个模型
  "models": [
    { "id": "opencode/deepseek-v4-flash-free", "contextWindow": 16000, "free": true }
  ],
  // 可选：临时停用整个通道
  "disabled": false
}
```

### Schema 校验（zod，与现有 Config 同风格）

```
channelFile = {
  id: string(required), displayName: string(default=id),
  baseUrl: string(required, must be http/https),
  apiKey: string(default=''), apiKeyEnv: string(default=''),
  models: array[{ id: string(required), contextWindow: int(optional), free: bool(optional) }] min 1,
  disabled: bool(default=false),
}
```

### 合并为链 entry（映射规则）

每个外部通道的每个模型 → 一条 `entry`：

```
{ provider: '<id>', model: '<model.id>', baseUrl: '<baseUrl>', apiKeyEnv: '<apiKeyEnv 或空>' }
```

- key 处理：`apiKeyEnv` 非空 → 原样传给 `readApiKey`（现有逻辑）；否则若文件里有明文 `apiKey` → **新增**：`openAiCompatStream` 支持 `apiKey` 直接注入（见 §7 改动点 C）；两者皆空 → 不发送 Authorization（桥接本地回环场景正好适用）。
- `contextWindow` 存入外部通道元数据，供 `resolveModelInfo` 兜底时返回真实窗口（当前默认 1000000，见 L535）。

## 5. 目录约定与发现机制

| 项 | 设计 |
|---|---|
| 配置字段 | `channelDir: string`（默认 `''` = 关闭） |
| 扫描范围 | `channelDir` 顶层 `*.jsonc` / `*.json`（非递归） |
| 启动 | `apply()` 内同步全量扫描一次（失败不阻断插件启动，仅日志） |
| 自动刷新 | `fs.watch(channelDir)` 监听 change/rename（主机制，秒级） |
| 手动刷新 | 注册 `POST /api/dsh-smart-route/refresh`（`webServer` 路由，仅 127.0.0.1）：重扫并返回通道清单（不回显 key）；附 `refresh-channels.ps1 / .cmd` 一键脚本 |
| 缓存失效 | 渠道池整体替换（下个请求生效），**无需重启** |
| 下线 | 文件删除 → 通道从渠道池移除；已引用它的链 entry 补全失败 → 该 entry 请求前跳过 + 日志，切下一家 |

## 6. 合并语义与路由行为

1. **不自动进链**：外部通道只进入「半注册渠道池」，任何既有链的默认行为不变；用户建链时手动把通道加进链。
2. **entry 引用与补全**：链上 entry 若 `provider` 命中渠道池中的通道 id（如 `opencode-free`）：
   - entry 未填 `baseUrl` → 自动用通道文件的 `baseUrl`（entry 显式填了则以 entry 为准，允许覆盖）；
   - key：entry 的 `apiKeyEnv` → 通道文件的 `apiKeyEnv` → 通道文件明文 `apiKey`（取第一个非空）；
   - `model` 不在该通道 `models` 列表内 → 该 entry 判无效，请求前跳过 + 日志（避免浪费一次上游请求）。
3. **模型选择**：模型选择器仍只显示链名（`listModels` 不变）；`resolveModelInfo` 命中外部通道时用文件里的 `contextWindow`（未命中沿用默认 1000000）。
4. **降级**：外部通道 400（如桥接拒绝 tools）/ 401 / 超时 → 冷却该通道 → 自动切链上下一家（全错误降级现有行为，无需改）。
5. **工具**：上游支持 tools（任意 OpenAI 兼容 API）→ 直接可用；不支持（当前桥接）→ 请求在流式开始前失败，正确回退，**不会污染已输出的内容**（`forwardedContent` 保护 L454-457 已存在）。
6. **优先级**：外部通道只出现在用户手动放入的链里，不抢占默认链。

## 8. 错误容忍与安全边界

- **单文件错误**：跳过该文件 + `ctx.logger.warn`，其余通道不受影响；`status` 面板可见错误原因。
- **目录不存在/不可读**：视为空通道集，仅日志提示，不阻断启动。
- **信任模型**：`channelDir` 视为本机信任源（同 opencode `auth.json` 同级风险）。
  - 建议目录放在用户目录下（如 `~/.dsh/channels/`），**不要**放共享/同步目录；
  - 明文 `apiKey` 场景在 README 提示：勿提交 git（文档建议加 `.gitignore`）；
  - `baseUrl` 仅允许 `http/https`，README 提示优先 `127.0.0.1` 或可信端点。
- **代理**：`fetch` 行为随 Harness 进程 env；2026-08-17 已通过 portproxy 让 `7897→7890` 复活（见经验库坑 4 修正），外部通道即使继承失效代理 env 也能走通；若代理再失效，全错误降级会切走并冷却，不阻塞会话。
- **手动刷新端点**：`POST /api/dsh-smart-route/refresh` 挂在 dsh web 的 127.0.0.1 监听上，无鉴权；handler 只做「重扫 + 返回通道清单（id/displayName/modelCount/file/error，**绝不回显 apiKey 明文**）」，无副作用，本机进程触发可接受。

## 12. 那么，代价是什么？

1. **信任面外移**：通道文件是 Harness 外的可执行配置源（url + key）。文件被篡改 = 请求被导向任意端点、key 被冒用。缓解：只放本地用户目录、README 明确不提交 git、状态面板可审计。代价可接受，与 opencode `auth.json` 同级。
2. **热更新靠 fs.watch + 手动刷新**：`fs.watch` 在 Windows/网络盘上可能漏事件——漏了手动跑一次 `refresh-channels.cmd`（一条命令）即可；**无常驻轮询开销**（通道变更本就是低频人工编辑）。
3. **多了一个长期维护点**：通道文件格式是插件 API 的一部分，将来升级要保证向后兼容（`id` 冲突语义、字段增删都要平滑）。建议格式版本号（`$schema`/`version` 字段）留给二期。
4. **不解决「免费编码」**：外部通道让任何 OpenAI 兼容端点都能进路由，但当前 opencode 桥接仍不支持 tools——包含外部通道的链上编码会话（带工具）会降级到下一家。这是通道能力问题，不是插件问题；未来桥接支持 tools 或接入支持 tools 的免费端点后自动受益。
5. **重启要求**：插件代码改动必须重启 `dsh web` 才生效（内存模块），需遵守重启红线二次确认。

## 13. 决策点（2026-08-17 已确认）

1. `channelDir` 默认 `''`（显式配置才启用，避免行为突变）—— ✅ 已确认。
2. **不自动生成外部链**；用户按需在设置卡手动新建链 / 填写渠道，`provider` 填外部通道 id（如 `opencode-free`），url + key 由插件从文件自动补全—— ✅ 已确认。
3. **支持明文 `apiKey`**（opencode 场景用明文写入；`apiKeyEnv` 仍优先）—— ✅ 已确认。
4. **不做** opencode.jsonc / auth.json 导出脚本—— ✅ 已确认。

### 实施时待实测点

1. 外部通道清单能否经 settings snapshot 透传给 client（`dsh-settings` 的 `scope.get()` 是否剥离未知字段）：
   - 能 → 设置卡渠道编辑行加「外部通道 ▾」下拉，点选一键填充 provider + 默认 model（改动 G 落地）；
   - 不能 → 用户手填通道 id，README 列出可用 id 清单（改动 G 降级为 hint 文案）。
2. `webServer.register` 挂载 `POST /api/dsh-smart-route/refresh` 在运行中组合的实际可用性（类型契约已确认：`WebRoute = { kind: 'exact', path, handler(req, res) }`，`ctx.get('webServer')` 可选获取；需沙盒实测挂载 + 请求返回）。

两者都不影响 host 端核心功能（外部通道扫描与补全不依赖它们）。
